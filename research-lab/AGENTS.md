# Rules for automated and human research contributions

The user has authorized public publication of their own mathematical work in this research-lab area. That does not authorize disclosure of anyone else's private material or claims of a headline solution without evidence.

1. Read STATUS.md and the relevant checked-in claim/proof/certificate before choosing work. Use repository commit SHAs as provenance. Do not trust a prior chat summary as a theorem.
2. Fix the exact statement, domain, hypotheses, falsifier and acceptance test before an experiment. Preserve the distinction between all groups, a finite group class and an explicitly enumerated family.
3. Keep a(G), omega(G), graph coloring and isotropic-subspace cover directions straight. A clique gives a lower bound on covers; a constructed cover gives an upper bound. Matching witnesses certify equality.
4. Record actual executions and timeouts. New finite results need a complete stated domain and a checker that reconstructs the key predicates independently. A success flag is not sufficient. No GPU or paid API is required or authorized by this file.
5. Lean proofs must build against the pinned lean-toolchain. No admitted proofs or new axioms may be used to disguise gaps. Print theorem dependencies. A checked finite witness does not automatically formalize the group-to-graph reduction or a larger census.
6. Keep UNFORMALIZED/LEAN_PENDING separate from LEAN_VERIFIED_AT_COMMIT. No badge or prose may imply a CI pass that has not been observed for the exact commit.
7. Preserve failed hypotheses and corrected claims with their status. Suspend downstream claims if a dependency fails. Separate validity, literature priority and relevance.
8. Do not publish emails, recipient lists, private progress/contact ledgers, credentials, local personal paths or unpublished third-party manuscripts. Cite public sources instead of copying whole papers.
9. Only change this research-lab subtree and its dedicated CI workflow unless the user separately authorizes another scope. Do not alter existing sparse-ruler experiments, deployment, paper automation or schedules.
10. Publish one bounded contribution via a dated directory and reviewable commit/PR. Read the remote head before writing, avoid force pushes, record the actual resulting SHA and link. Unavailable tools mean a local release candidate, not a claimed upload.
11. This repository supplies a destination, not an autonomous AI service. Chat scheduling, model access and write access are separate. Never claim a Work session, additional model agent or experiment that did not execute.
